# Designed components

Generated by `node exporter/skill-refs.ts` from `data/v2/design-system.json`. Do not edit.

Neither Creative Tim kit drew these, so Argon v2 designs them from its own roles: plain HTML with `ar-*` classes, no Figma node. 43 components are new; 4 existing components gained variants (button states, alert kinds, outline colors).

**To use one in code:** install the base styles first, then the component styles, then write the markup from `get_component` (it prints the markup of a variant, the classes, the states and what script the page must add).

```bash
node tools/argon.mjs tokens-css > tokens.css
node tools/argon.mjs base-css --no-vars > base.css
node tools/argon.mjs components-css > components.css
```

Rules: icons are `<i class="ar-icon" data-icon="name">` (swap for an inline Font Awesome SVG, `get_icon`); states are attributes (`aria-expanded`, `aria-selected`, `aria-current`, `aria-busy`, `aria-invalid`, `disabled`, `data-state`); the CSS is visual only, the page adds the script named under Behavior.

## `table-toolbar` — Table toolbar

The bar above a data table: search, filters, a column picker, the result count, and bulk actions that take over when rows are selected.

Classes: `ar-toolbar` `ar-toolbar__row` `ar-toolbar__search` `ar-toolbar__filters` `ar-toolbar__filters-toggle` `ar-toolbar__tools` `ar-toolbar__count` `ar-toolbar__btn` `ar-toolbar__btn--danger` `ar-toolbar__badge` `ar-toolbar__apply` `ar-toolbar__chips` `ar-toolbar__chip` `ar-toolbar__chip-key` `ar-toolbar__chip-remove` `ar-toolbar__clear` `ar-toolbar__selected` `ar-toolbar__actions` `ar-toolbar--bulk` `ar-toolbar--phone`
States: default, hover, focus, filter active, filter menu open, rows selected, disabled
Accessibility: The wrapper is role="toolbar" with an aria-label that names the table. Every control is a real button or input with a visible or aria-label name. A filter button that opens a menu has aria-haspopup="menu" and aria-expanded; an active filter also shows a count so the state is not colour only. The result count is role="status" so a screen reader hears 'Showing 12 of 48 vehicles' after a change. Each chip's remove button says what it removes ('Remove filter Status: In service'). Tab goes search, filters, count, Columns; in the bulk bar it goes actions, then Clear. When the bulk bar appears, move focus to it or announce '3 selected' through its role="status"; after Clear, return focus to the header checkbox.
Behavior: Filter buttons open a dropdown-menu or popover; applying a filter adds a chip and updates the count. Search filters on input with a short debounce. Selecting a row swaps the standard bar for the bulk bar; Clear (or unchecking the last row) restores it. On phone the Filters button toggles aria-expanded on itself and shows the filter list.
On mobile (collapse): Search takes the first row full width. The filter buttons collapse behind one Filters button with a count badge, opened as a stacked list with an Apply button. Columns and the result count sit beside it. The bulk bar becomes two rows: '3 selected' and Clear on top, the actions below.

## `table-sort-header` — Table sort header

Column headers of a data table that sort the rows: an unsorted, ascending or descending state, a numeric header, a filter icon and a select-all checkbox.

Classes: `ar-sort` `ar-sort__head` `ar-sort__head--end` `ar-sort__btn` `ar-sort__arrow` `ar-sort__filter` `ar-sort__select` `ar-sort__check`
States: unsorted, ascending, descending, hover, focus, filter active, row selected, mixed selection
Accessibility: Put aria-sort="ascending", "descending" or "none" on the th that is sortable; only one header carries ascending or descending. Inside the th, a real button holds the label, so Enter and Space sort and Tab reaches every header. Leave the arrow icons aria-hidden: aria-sort already tells assistive technology the state. After a sort, announce it in a role="status" line ('Sorted by distance, descending') or keep focus on the same button. A filter button has its own aria-label ('Filter Status') and aria-haspopup. The header checkbox is a checkbox named 'Select all vehicles'; when only some rows are selected set the indeterminate property and aria-checked="mixed". Selected rows carry aria-selected="true".
Behavior: Clicking a header button cycles none, ascending, descending, and moves aria-sort to that th (removing it from the others). The page sorts the data. The header checkbox selects every visible row and sets indeterminate when only some are selected.
On mobile (scroll): The table scrolls sideways inside its own frame (data-scroll) instead of squeezing the columns, and every header button and checkbox is at least 44px. Put the vehicle column first so it is the one people read while scrolling.

## `sparkline` — Sparkline

A tiny trend chart with no axes that sits inside a table cell or a stat card and shows the shape of recent data at a glance.

Classes: `ar-spark` `ar-spark--lg` `ar-spark--positive` `ar-spark--negative` `ar-spark__line` `ar-spark__area` `ar-spark__bar` `ar-spark__bar--last` `ar-spark__dot` `ar-spark__base` `ar-spark-stat` `ar-spark-stat__text` `ar-spark-stat__label` `ar-spark-stat__value` `ar-spark-stat__delta` `ar-spark-stat__delta--positive` `ar-spark-stat__delta--negative` `ar-spark-table`
States: default, positive, negative, neutral
Accessibility: The svg has role="img" and an aria-label that gives the whole summary: what it measures, the period and the change ('Fuel use, last 7 days, down 4%'). Never rely on colour alone: the label and the visible delta text say up or down, and the colour only says good or bad. If the same facts are already written next to the chart, keep the label anyway. Sparklines are not focusable; if a tooltip with values is needed, make the cell or card the focus target and put the values in text.
Behavior: Compute the points from the series: x evenly spaced, y scaled between the series min and max (bars from zero). Update the polyline points when new data arrives. Pick ar-spark--positive or ar-spark--negative from whether the change is good for the metric, not from its sign.
On mobile (same): Same size. In a table the trend column stays, and the table's own horizontal scroll takes over if the row would not fit; on a stat card the sparkline moves under the number only if the card is narrower than 14rem.

## `banner` — Banner

A full-width bar at the top of a page or card that announces a status or an upcoming change, with an optional action link and a dismiss button.

Classes: `ar-banner` `ar-banner--info` `ar-banner--success` `ar-banner--warning` `ar-banner--danger` `ar-banner--card` `ar-banner__icon` `ar-banner__text` `ar-banner__action` `ar-banner__close`
States: default, hover, focus, dismissed
Accessibility: Give the bar role="status" (info, success, warning) or role="alert" (danger) so a screen reader announces it when it appears; a banner that is on the page at load needs no live region. The icon is decorative (aria-hidden). Color is never the only signal: the bold lead sentence says what happened. The action is a real link or button with a text label. The close button needs an aria-label that names the notice ("Dismiss maintenance notice"), is a native button (Enter and Space), and after dismissal focus moves to the next sensible element, not to the top of the page.
Behavior: Dismiss removes the banner (or sets hidden) and may store the choice so it does not return on the next visit; a danger banner should not be dismissible until the problem is fixed.
On mobile (reflow): The text takes the full width beside the icon and the close button; the action link drops to its own row under the text, aligned with it. Targets grow to 44px.

## `split-button` — Split button

A primary action with an attached caret that opens a short menu of related actions.

Classes: `ar-split` `ar-split--end` `ar-split__group` `ar-split__main` `ar-split__toggle` `ar-split__menu` `ar-split__item` `ar-split__item--danger` `ar-split__sep`
States: default, hover, focus, active, open, disabled
Accessibility: The toggle is a button with aria-haspopup="menu", aria-expanded (true while the menu is open) and aria-controls pointing at the menu; its aria-label says what the menu holds ("More ways to add a trip") because it has no text. The menu has role="menu", every entry role="menuitem" inside an li with role="none", and the divider role="separator". Keyboard: Tab reaches the main button, then the toggle; Enter, Space or Arrow Down on the toggle opens the menu and focuses the first item; Arrow Up and Down move, Home and End jump, Esc closes and returns focus to the toggle, Tab closes the menu.
Behavior: Toggle aria-expanded on click; close on outside click, Esc and after an item runs; move focus into the menu when it opens and back to the toggle when it closes. The main button runs the default action and never opens the menu.
On mobile (same): Same layout. The menu stays under the button, at least 14rem wide and never wider than the screen; add ar-split--end when the button is on the right. For menus longer than five items use a bottom sheet instead.

## `button-group` — Button group

Joins two to five related buttons into one bordered control, either as a toggle where one option is selected or as a set of separate actions.

Classes: `ar-btn-group` `ar-btn-group--primary` `ar-btn-group__item` `ar-btn-group__item--icon`
States: default, hover, focus, active, selected, disabled
Accessibility: The wrapper has role="group" and an aria-label naming the control ("Report period"), or role="radiogroup" when exactly one option is always selected. Toggle buttons expose their state with aria-pressed; radio items use role="radio" and aria-checked with a roving tabindex (selected item tabindex 0, the others -1). Keyboard: Tab enters the group; in a radiogroup Arrow Left and Right move and select, in a plain group each button is a Tab stop; Space and Enter activate. Icon-only items carry an aria-label; the selected state is shown by a filled background, not by color alone, and also read out by the aria attribute.
Behavior: Toggle: on activation set aria-pressed (or aria-checked) true on the new item, false on the others, and update the content. Actions: run the command; no selected state.
On mobile (reflow): Text groups stretch to the full width and share it equally, so each segment is an easy thumb target; icon-only groups keep their size. Keep labels to one short word so three or four segments fit in 358px.

## `fab` — Floating action button

A round button that floats over a screen and holds its single most important action, such as adding a trip.

Classes: `ar-fab` `ar-fab--extended` `ar-fab--small` `ar-fab--secondary` `ar-fab--fixed` `ar-fab__label` `ar-fab-frame` `ar-fab-frame__row`
States: default, hover, focus, active, disabled
Accessibility: A native button. An icon-only FAB must have an aria-label that names the action ("Add trip"); the extended one gets its name from the visible label. The icon is decorative. Place it last in the DOM order of the screen content so keyboard users reach it after the list, and make sure it never covers the last row of content: add bottom padding to the scroll area at least the FAB's height plus its offset.
Behavior: Runs one action on click (open a form or sheet). An extended FAB may shrink to a round one while the list scrolls down and extend again on scroll up.
On mobile (same): This is where it belongs: fixed at the bottom right with 16px margin plus the device safe area. On desktop prefer a button in the page header.

## `form-field` — Form field

The wrapper every input needs: a label, optional help, the control, and a message for an error or a success, all wired together for screen readers.

Classes: `ar-field` `ar-field__label` `ar-field__required` `ar-field__optional` `ar-field__hint` `ar-field__message` `ar-field__message--error` `ar-field__message--success` `ar-field__action` `ar-field--inline` `ar-field-group`
States: default, focus, error, success, disabled
Accessibility: Use a real <label for> that points at the control's id, never a placeholder as the label. Give the hint an id and list it in the control's aria-describedby. On error set aria-invalid="true" on the control, render the message with an id and role="alert" (so it is read when it appears), and add that id to aria-describedby after the hint. Classes: `ar-ctx__stage` `ar-ctx__stage--table` `ar-ctx__table` `ar-ctx__plate` `ar-menu` `ar-menu--plain` `ar-ctx-menu` `ar-ctx-menu__title` `ar-menu__item` `ar-menu__label` `ar-menu__divider` `ar-menu__item--danger` `ar-ctx__stage--map` `ar-ctx__map` `ar-ctx__pin` `ar-menu__icon` `ar-menu__hint` `ar-ctx__stage--tall` `ar-menu__sub` `ar-menu__chevron` `ar-menu__check` `ar-ctx__stage--phone` `ar-ctx__list` `ar-ctx__card` `ar-ctx__card-text` `ar-ctx__card-title` `ar-ctx__card-meta` `ar-ctx__status` `ar-ctx__scrim`
States: open, hover, active (keyboard highlight), focus, disabled, submenu open, target highlighted
Accessibility: The menu has role="menu" and an aria-label that names the item ("Actions for TRK-2041"); rows are role="menuitem" (or menuitemcheckbox, menuitemradio) with a roving tabindex, dividers role="separator". Keyboard: the target row or pin must be focusable; the Menu key or Shift+F10 opens the menu at the focused item (right-click and long press are shortcuts, never the only way); Up, Down, Home, End and type-ahead move; Right opens a submenu, Left closes it; Enter runs; Esc closes and returns focus to the target. The row that owns the menu keeps a visible highlight (data-state="context") while the menu is open. On touch, a long press must not also select text: set user-select to none on the target and prevent the native callout. Screen readers do not hear a long press: the same commands must exist on a button.
Behavior: Listen for contextmenu (prevent default only inside the target), the Menu key, Shift+F10 and a 500ms touch hold. Place the menu at the pointer, flip it left or up near the viewport edges, focus the first row, close on outside press, scroll, resize, Esc and after a command. On a phone width, render it as the bottom list (the CSS does it) and close on scrim tap.
On mobile (sheet): Becomes a bottom list: full width, rounded top corners, a title with the item name, 48px rows, no keyboard hints, and a submenu opens inline under its row. Opened by long press.

## `mega-menu` — Mega menu

A large navigation panel that drops under a navbar item and lists many destinations in titled columns, with a featured card and a footer link.

Classes: `ar-mega` `ar-mega__bar` `ar-mega__item` `ar-mega__trigger` `ar-mega__chevron` `ar-mega__panel` `ar-mega__panel--feature` `ar-mega__col` `ar-mega__heading` `ar-mega__toggle` `ar-mega__list` `ar-mega__link` `ar-mega__icon` `ar-mega__text` `ar-mega__title` `ar-mega__desc` `ar-mega__feature` `ar-mega__media` `ar-mega__feature-title` `ar-mega__feature-text` `ar-mega__more` `ar-mega__footer` `ar-mega--stacked`
States: closed, open, hover, focus, current page, expanded section (phone), collapsed section (phone)
Accessibility: Use a disclosure pattern, not role="menu": the whole navbar is a nav with an aria-label; each trigger is a button with aria-expanded and aria-controls pointing at its panel; the panel holds ordinary links in lists with headings (h3) per column. Tab moves through the links in order; Esc closes the panel and returns focus to its trigger; Enter or Space on the trigger toggles it; opening on hover is allowed only as an addition, never the only way. The current page link carries aria-current="page". On a phone the heading is replaced by a button (aria-expanded, aria-controls the list) and the list is hidden when collapsed. The decorative icons are aria-hidden.
Behavior: Toggle aria-expanded on the trigger and show or hide the panel; close on Esc, outside click, focus leaving the panel and when another trigger opens. On hover, open after about 150ms and close after about 300ms so the pointer can cross the gap. On phone, toggle aria-expanded on each column button (one open at a time is recommended); the CSS shows or hides the list.
On mobile (collapse): The bar stacks as a vertical list and each panel opens inline under its item. Each column's heading becomes a full-width toggle button with a chevron, so the columns are an accordion. The featured image is dropped and the footer links stack.

## `command-palette` — Command palette

A centered search-and-run dialog: type to find a vehicle, a page or an action, then press Enter to go or run it.

Classes: `ar-palette__stage` `ar-palette__page` `ar-palette__bar` `ar-palette__scrim` `ar-palette` `ar-palette__search` `ar-palette__input` `ar-palette__list` `ar-palette__group` `ar-palette__group-title` `ar-palette__option` `ar-palette__glyph` `ar-palette__text` `ar-palette__title` `ar-palette__meta` `ar-palette__hint` `ar-palette__hint--always` `ar-palette__footer` `ar-palette__keys` `ar-palette__status` `ar-palette__spinner` `ar-palette__skeleton` `ar-palette__empty` `ar-palette__empty-title` `ar-palette__empty-text`
States: empty query (suggestions), typing (results), highlighted result, loading, no matches, focus
Accessibility: The panel is role="dialog" with aria-modal="true" and an aria-label. Inside, the input is role="combobox" with aria-expanded, aria-controls pointing to the listbox, aria-autocomplete="list" and aria-activedescendant naming the highlighted option; the results are role="listbox" with role="group" sections labelled by their heading and role="option" rows with aria-selected on the highlighted one (focus stays in the input). Keyboard: Ctrl or Cmd plus K opens and focuses the input; Down and Up move the highlight and wrap; Home and End go to the first and last result; Enter runs the highlighted result; Esc closes and returns focus to what had it; Tab stays inside the dialog. When the query changes, announce the count with a polite live region ("6 results") and role="status" for "No matches". While loading, set aria-busy="true" on the listbox and announce "Searching".
Behavior: Open on the shortcut, trap focus, lock page scroll, debounce the query about 150ms, group results by kind, keep the first result highlighted, scroll the highlighted option into view, close on Esc, on scrim tap and after a result runs. Return focus to the previously focused element on close. Remember recent choices.
On mobile (fullscreen): Fills the whole screen with no corner radius; the keyboard hint footer is hidden because touch has no keyboard; the results scroll under a fixed search field; rows are 44px tall. Open it from a search button, since there is no shortcut.

## `tree-view` — Tree view

An expandable hierarchy such as fleet, depot and vehicle, where the user opens branches and selects or checks nodes.

Classes: `ar-tree` `ar-tree__item` `ar-tree__row` `ar-tree__chevron` `ar-tree__icon` `ar-tree__label` `ar-tree__count` `ar-tree__chevron--none` `ar-tree__meta` `ar-tree__box`
States: collapsed, expanded, hover, focus, selected, checked, partly checked, disabled
Accessibility: Container role="tree" with an aria-label (add aria-multiselectable="true" when several rows can be selected or checked); each row is role="treeitem" with aria-level, aria-setsize and aria-posinset; a branch has aria-expanded and holds its children in a role="group" list; the selected row has aria-selected="true" (or aria-checked true, false or mixed in a checkbox tree). Only one treeitem is in the tab order (tabindex 0, the others -1, roving). Keyboard: Down and Up move to the next and previous visible row; Right opens a closed branch, and on an open branch moves to its first child; Left closes an open branch, and on a child or closed branch moves to the parent; Home and End go to the first and last visible row; Enter selects or activates; Space toggles the checkbox in a checkbox tree; * opens all siblings; typing a letter jumps to the next row starting with it. Chevrons, icons and the drawn checkbox are aria-hidden: the state is on the treeitem.
Behavior: Script toggles aria-expanded (the CSS hides a closed group), moves tabindex and focus, sets aria-selected or aria-checked, and in a checkbox tree computes a parent's mixed state from its children and applies a parent's change to all its children. Lazy-load children when a branch opens for the first time.
On mobile (same): Rows are 44px tall, the indent per level is 1.25rem, and the meta text column is hidden so labels keep their room; the count stays.

## `drawer` — Drawer

A panel that slides in over the page from the right or left edge to hold filters, details or a secondary task, without leaving the page.

Classes: `ar-drawer__stage` `ar-drawer__page` `ar-drawer__bar` `ar-drawer__scrim` `ar-drawer` `ar-drawer--md` `ar-drawer__header` `ar-drawer__heading` `ar-drawer__title` `ar-drawer__subtitle` `ar-drawer__close` `ar-drawer__body` `ar-drawer__group` `ar-drawer__chips` `ar-drawer__chip` `ar-drawer__row` `ar-drawer__footer` `ar-drawer--lg` `ar-drawer__facts` `ar-drawer__status` `ar-drawer__section` `ar-drawer__note` `ar-drawer__section--spaced` `ar-drawer--left` `ar-drawer--sm` `ar-drawer__nav` `ar-drawer--full`
States: open, closing, focus, scrolling body, left, right
Accessibility: The panel is role="dialog" with aria-modal="true" and aria-labelledby the title (an h2). On open, move focus to the first control or to the title (tabindex=-1) and trap Tab inside; make the rest of the page inert. Esc and the close button close it and focus returns to the control that opened it; clicking the scrim also closes it. The close button has an aria-label ("Close filters"). A body that scrolls is a focusable region (tabindex=0 with an aria-label) so keyboard users can scroll it. Toggle chips use aria-pressed. Respect reduced motion: the slide becomes a fade.
Behavior: Open by toggling the dialog and the scrim, lock page scroll, trap focus, set inert on the rest of the page, remember the opener and restore focus on close. Slide with a transform over motion.duration.slow. Apply the footer's primary action, then close; Reset clears the form without closing.
On mobile (fullscreen): The drawer becomes full width and full height (no side border), the footer actions share the row equally, and the header padding tightens. For a short confirmation use a bottom-sheet instead.

## `hover-card` — Hover card

A small rich card that appears when a pointer rests on, or keyboard focus reaches, a link or an avatar, to preview who or what it points to.

Classes: `ar-hover__stage` `ar-hover__sentence` `ar-hover` `ar-hover__trigger` `ar-hover__trigger--inline` `ar-hover__card` `ar-hover__head` `ar-hover__avatar` `ar-hover__name` `ar-hover__role` `ar-hover__stats` `ar-hover__stat` `ar-hover__actions` `ar-hover__stage--bottom` `ar-hover__avatar-link` `ar-hover__avatar--sm` `ar-hover__status`
States: closed, open, focus, placement below, placement above
Accessibility: The trigger is a real link (or a button) that works without the card: keep its name meaningful ("Amina Rahal", or aria-label="Amina Rahal, driver" on an avatar). Show the card on both hover and keyboard focus, and set aria-expanded on the trigger with aria-controls pointing to the card. Esc closes the card and keeps focus on the trigger. The card is role="group" with an aria-label; do not use role="tooltip", because it holds buttons. Keep the card next to the trigger in the DOM so Tab moves into its buttons; when focus leaves both, close it. Never rely on the card for essential facts, because touch and screen reader users may not get it.
Behavior: Open on pointerenter and focusin after a delay, close on pointerleave of both trigger and card, on focusout of both, and on Esc. Set data-state to open or closed and data-placement to below or above after measuring the space. Do not open it on touch pointers.
On mobile (swap): No hover on a phone: the hover card is not shown. Tapping the name or avatar opens the target page, or a bottom-sheet with the same name, stats and buttons. If the card ever appears (a keyboard on a phone) it is capped at the screen width minus 32px.

## `lightbox` — Lightbox

A full-screen viewer that shows one photo at a time over a dark scrim, with a caption, a counter and previous and next controls.

Classes: `ar-lightbox` `ar-lightbox__top` `ar-lightbox__counter` `ar-lightbox__tools` `ar-lightbox__btn` `ar-lightbox__btn--prev` `ar-lightbox__figure` `ar-lightbox__image` `ar-lightbox__btn--next` `ar-lightbox__caption` `ar-lightbox__caption-title` `ar-lightbox__caption-meta` `ar-lightbox__image--b` `ar-lightbox__thumbs` `ar-lightbox__thumb`
States: open, loading image, first photo (previous disabled), last photo (next disabled), hover, focus, current thumbnail
Accessibility: The viewer is role="dialog" with aria-modal="true" and an aria-label ("Photo viewer" or the gallery's name). Move focus to the close button or the dialog on open, trap Tab inside, make the page inert, and return focus to the thumbnail that opened it on close. Esc closes; Left and Right arrows go to the previous and next photo; Home and End jump to the first and last. The image has a text alternative (aria-label on a placeholder, alt on an img); the counter is aria-live="polite" so "3 / 12" is announced when it changes; every icon button has an aria-label. At the ends the arrow is disabled. Thumbnails are buttons with aria-label; the current one has aria-current="true". While an image loads set aria-busy="true" on it.
Behavior: Open from a thumbnail, lock page scroll, trap focus, show the loading state until the image decodes, preload neighbors, step with the arrows, the keys and horizontal swipe, close on Esc, on the close button and when the scrim around the image is clicked. Pinch or double-tap may zoom.
On mobile (reflow): The image fills the width. The previous and next buttons move below the caption, to the left and right ends, so they are easy to reach with a thumb; swipe also steps. The thumbnail strip wraps onto a second row instead of scrolling sideways.

## `bottom-sheet` — Bottom sheet

A panel that rises from the bottom of a phone screen for a short confirmation, a list of choices or a form, and is dismissed by tapping outside or swiping down.

Classes: `ar-sheet__frame` `ar-sheet__page` `ar-sheet__bar` `ar-sheet__scrim` `ar-sheet` `ar-sheet__handle` `ar-sheet__header` `ar-sheet__header--plain` `ar-sheet__title` `ar-sheet__body` `ar-sheet__text` `ar-sheet__footer` `ar-sheet__danger` `ar-sheet__choices` `ar-sheet__choice` `ar-sheet__choice-icon` `ar-sheet__choice--danger` `ar-sheet__close` `ar-sheet__field` `ar-sheet__footer--sticky` `ar-sheet__map` `ar-sheet__pin` `ar-sheet--peek` `ar-sheet__summary`
States: open, closing, dragging, scrolling body, peek (collapsed), expanded, focus
Accessibility: Modal sheets are role="dialog" with aria-modal="true" and aria-labelledby the title; the peek sheet is role="dialog" with aria-modal="false" and an aria-label, and the page behind stays usable. On open move focus to the first control (or the title for a confirmation: tabindex=-1 on the title) and trap it, for a modal sheet; restore focus to the opener on close. Swipe down and scrim tap are shortcuts: always give a visible way to close (a Cancel button, a close button) and let Esc close it. The grab handle is decorative (aria-hidden); on the peek sheet make it a button with aria-expanded and aria-label "Expand vehicle details" so the sheet can open without a swipe. Choices are real buttons in a list. Respect reduced motion: use a fade.
Behavior: Rise with a transform over motion.duration.slow; track the pointer on the handle to drag, close when dragged down more than about a third or released with a fast downward swipe; close on scrim tap and Esc; lock page scroll behind a modal sheet; keep the sticky footer above the on-screen keyboard (use dvh units and visualViewport). Cap height at 90% and scroll the body.
On mobile (sheet): This is the phone form: full width, pinned to the bottom, rounded top corners, buttons full width with 44px height at least, content up to 90% of the viewport height.
